# write-docs

人が読む文書を、読み手から逆算して書く。規則は少なく、守れば判定できるものだけにしてある。

## 手順
1. **読み手を決める。** 誰が、何を知らずに、何をしに読むかを 1 行で書く。決められなければ、書き始めない。
2. **置き場所を決める。** 下の表で、既存の文書に入るか確かめる。入るなら、その文書に書く。
3. **結論を先に書く。** 冒頭に読み手と目的（1〜2 行）、続けて要旨（3〜5 行）。
4. **本文を書く。** 見出しは主張。1 段落 1 主題、第一文に要点。
5. **図と表を選ぶ。** 値を引く・少数を比べるなら表。傾向・差・例外が主張なら図。
6. **5 つの試験を通す。** 通らなければ直す。
7. **検査を回す。** リポジトリに検査があれば（リンク、アンカー、表の幅、読み手の行、図の一致）、すべて通す。

## 文書の役割
| 書くこと | 文書 |
|---|---|
| 答え 3 行、読む順番、最短の使い方 | README（入口） |
| 結論。要旨 → 結論 → 理由 → 信頼できる範囲 → 付録 | report（主役） |
| 構成と仕様の事実の一覧 | architecture |
| 動かし方、後片付け、つまずきやすい点 | runbook |
| 確かめた個別の事実（結論と根拠を分ける） | findings |
| 用語と呼び名の対応 | glossary |
| 計画（なぜ・何を・どう測るか、予測、基準） | internal/plan |
| 経過（日付、判断、費用の実績、次の候補） | internal/log |
| 設計の判断と理由 | internal/design-decisions |

計画と結論の文書に、日付・状況・費用の実績は書かない。経過に書く。

## 規則
- 冒頭に、読み手と目的を 1〜2 行で書く。結論を先に書く。
- 1 文書 1 役割。同じ内容を 2 か所に書かず、リンクする。
- 見出しは、言いたいことを書く。曖昧な見出し（「一般」「範囲」）は使わない。
- 1 段落 1 主題、第一文に要点。1 文 1 義。「これ」「それ」を避け、名詞を繰り返す。
- 事実・推定・意見を分ける。推定は「推定」と書き、根拠を添える。
- 用語は初出で定義するか、用語集にリンクする。同じ概念は同じ語で書く。
- 数字は、本文では 1 段落に 3 個まで。丸めて代表値を書き、ばらつきは付録へ。同じ数字は 1 か所に書く。
- 表は 1 表 1 メッセージ、5 列以内。
- 人が読む文書は日本語で書く（利用者の言語に合わせてよい）。AI を主語にしない。
- 数値の実績、認証情報、アカウント ID、メールアドレスを、雛形や例に入れない。

## 5 つの試験
1. **30 秒:** タイトルと冒頭だけで、何の文書で、結論が何か分かる。
2. **見出し:** 見出しだけ読んで、筋が通る。
3. **第一文:** 各段落の第一文だけ読んで、要約になる。
4. **用語:** 初出の略語・構成名・ケース名に、定義かリンクがある。
5. **数字:** 結論の段落の数字が 3 個以内。

## 図
- SVG で作り、生成するコードをリポジトリに置く。Mermaid は使わない。
- 部品は、箱・グループ・矢印・枠（構成図）と、棒・積み上げ棒（グラフ）。ライトとダークの両方に対応させる。
- 系列の色は 5 色までの検証済みの順（1 番から）を使い、系列は 3 つまでにする。
- 図は画像にして目で確かめる（はみ出し、重なり、矢印の向き、ダーク表示）。
- 図には、読み上げ用の title と desc を付ける。文書には、何の図かを 1 文で書く。
- 生成物をリポジトリに置き、生成し直して一致することをテストで調べる。
