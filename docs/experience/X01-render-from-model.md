# X01：モデルから構成図を描く

## 状況

チームの文法（[benchmarks/sample-arch/grammar.md](../../benchmarks/sample-arch/grammar.md) の軸、領域、線の種類、グループ）が、ファイルとしてリポジトリにある。描く人は、注文システムの構成図のモデルを書き終えた。モデルには、ノード、グループ、線と、それぞれの属性（`trust: external`、`mode: async`、`concern: cross-cutting`、線の `kind`）だけを書き、座標は書いていない。

## 操作

```
npx kothar render architecture.kothar --out architecture.svg
```

コマンドの名前、引数、ファイルの拡張子は、PR/FAQ と同じく仮である。

## 見えるもの

- `architecture.svg` と、配置の結果の JSON（各ノードの座標と大きさ、各線の経路の点列、各グループの枠）ができる。
- SVG では、モデルに書いた属性が、文法どおりの位置と線の形で表れている。
  - 外部のノード（IdP、決済代行）は、本流の上の帯にあり、呼び出す側（API Gateway、注文サービス）の真上にある。外部呼び出しの線は、呼び出す側の上の辺から真上へ伸びる。
  - 本流のノードは、呼び出す側が左、呼ばれる側が右に並び、同期の線は右の辺から出て左の辺に入る。
  - 非同期のノード（イベントキュー、通知ワーカー）は本流の下の帯にあり、非同期の線は破線である。
  - 横断的な関心事（ログ基盤、監視、鍵管理）は図の右端の列にあり、VPC の右辺から細い点線でつながる。
  - 逆向きの通知（通知ワーカーからユーザーへ）は、図の下を回る点線である。
- 元の手で描いた図（[handplaced.svg](../../benchmarks/sample-arch/handplaced.svg)）と並べると、要素の位置関係と線の意味が一致している。座標は一致しなくてよい。
