- 実施日：2026-10-09
- 関連する ADR：[0003](../adr/0003-ai-scope.md)、[0012](../adr/0012-plugin-engine-call.md)、[0013](../adr/0013-plugin-engine-delivery.md)

## 目的

フェーズ3の要件のうち、検証の方法が「AI の評価」のもの（R-AI-1、R-AI-2、R-AI-3、R-AI-5、R-AI-6、R-PLUGIN-2）を確かめる。あわせて、R-AI-4（人の確認）の材料として、AI の報告を残す。

## 方法

コミット 941fdf2 のプラグイン（`plugins/kothar`）を使った。依頼ごとに一時ディレクトリを作り、体験の例の入力を写して、そこで依頼した。

| 場面 | 依頼の方法 | 回数 | 依頼の文 |
| --- | --- | --- | --- |
| X10 | `claude -p`、`--plugin-dir plugins/kothar` | 3 | 「docs/process.md から、benchmarks/process/ の語彙と文法を使って、作業プロセスのモデルを下書きして。図も描いて。」 |
| X11 | 同上 | 3 | 「architecture.yaml の lint の誤りと違反を直して。」 |
| X12 | Agent SDK（[examples/agent-sdk/draft-model.mjs](../../examples/agent-sdk/draft-model.mjs)） | 1 | X10 と同じ |

- X10 と X12 の一時ディレクトリには、docs/process.md と、benchmarks/process/ の vocabulary.yaml、grammar.yaml、grammar.md を写した。手で書いたモデル（model.yaml）は写していない。
- X11 の一時ディレクトリには、[X11 の誤りを入れたモデル](../experience/X11/model-broken.yaml) を architecture.yaml として写し、サンプル構成図の語彙と文法を写した。
- AI に使わせた道具は、`Bash(kothar:*)`、Read、Write、Edit、Glob、Grep である。
- モデルは指定せず、Claude Code の既定に任せた。Claude Code の出力（`modelUsage`）には、claude-opus-5-5 と claude-haiku-4-5-20251001 があった。
- 判定は、各要件の「検証」の節の条件による。R-AI-3 では、AI が書いたモデルを [benchmarks/process/model.yaml](../../benchmarks/process/model.yaml)（コミット 941fdf2 の時点のもの）と比べた。

## 観察

1. **R-AI-3 で一致しなかったノードの多くは、手で書いたモデルのラベルが設計書の言葉と違っていたものだった。** 手で書いたモデルでは「検証する」「実装しテストを書く」「テスト」「体験」と書いたが、docs/process.md の言葉は「検証を行う」「実装し、要件の検証のテストを書く」「コードとテスト」「シナリオ」である。AI は4回とも設計書の言葉を使った。ラベルが違うノードにつながる線も、一致しなかった。
2. **手で書いたモデルには、設計書に書かれていない要素があった。** 「作業項目の一覧」と「対応表」は、docs/process.md に出てこない。AI はどの回もこの2つを書かず、設計書が参照している「計画」を書いた。
3. **属性は、ラベルの一致したノードのすべてで一致した。**
4. **AI は4回とも、lint の違反をなくすために、モデルの意味を変えた。** どの回も、変えたことと理由を報告していた。
   - 段階1から文書体系への参照の線が、段階1から段階2への線と同じ点から出て重なり（規則9）、参照の線を消すか、出どころを別のノード（「ADR を書く」）に移した（4回とも）。
   - 2本の「上流に戻る」線のうち1本が規則6の違反になり、2本を1本にまとめた（X10 の1回目、2回目）。
   - 責任者を承認ごとに5つのノードに分けた（X10 の3回目）。
5. **段階1から出る2本の線が重なったのは、エンジンの線の引き方による。** 端の列への線は経路探索で引き、段階2への線は ELK が引く。経路探索は、同じ辺から出る線の出る点を、経路探索で引く線の間でだけ分けており、ELK が引いた線の出る点を数えていない。
6. **「6. ゲート」から「1. 約束」へ戻る線は、4回とも描かれなかった。** AI は、次の段階への線（`next`）として描くと規則4に反し、設計書の「上流に戻るとき」にもないためと報告した。

## 限界

- **回数は、X10 と X11 が3回、X12 が1回だけである。**
- **R-AI-3 の比べ方は、ラベルの完全一致による。** 意味が同じで言葉が違うものは、一致しないものとして数えた。
- **AI の報告の中身（R-AI-4）は、この検証では判定していない。**
- **Linux でしか確かめていない。**
