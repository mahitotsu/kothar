# 検証 0006：ELK のパーティションで、入れ子のグループがあってもノードを列に並べられるか

- 実施日：2026-10-08
- 関連する ADR：[0001](../adr/0001-layout-approach.md)
- 検証のコード：[spikes/elk-partition/](../../spikes/elk-partition/)（elkjs 0.12.0、Node.js 24.21.0、Linux）

## 目的

[X08](../experience/X08-trust-boundary-view.md) の信頼境界の図は、ノードを3つの列（利用者側、信頼境界の中、外部のサービス）に並べる。ADR 0001 では、本体を ELK の layered で配置すると決めた。列を、ELK の layered のパーティション（`elk.partitioning`）で表せるかを確かめる。特に、列の1つが入れ子のグループ（VPC の中にアプリ層）であっても、列の順が守られ、グループのメンバーが枠からはみ出さないかを確かめる。

## 方法

X01 のモデルから、横断的な関心事のノード（ログ基盤、監視、鍵管理）と `uses` の線を除いたグラフを、ELK の layered で配置した。ルートに `elk.partitioning.activate` を指定し、ノードとグループに列の番号を `elk.partitioning.partition` で付けた。列は、ユーザーと CDN を0、VPC を1、IdP と決済代行を2とした。線の出入りの辺と、逆向きの線の反転は、エンジンと同じにした。

| 案 | パーティションを付けるもの |
| --- | --- |
| A | ルートの直下のノードとグループだけ |
| B | A に加えて、グループの中のノード（グループと同じ番号） |

判定：

- 列の順：ある列のノードの中心の x 座標が、それより左の列のどのノードの中心の x 座標よりも大きいか。グループの中のノードは、グループの列として扱った。
- グループのメンバーが、グループの枠の外にはみ出していないか。
- 決定性：同じプロセスで2回配置した結果の JSON を比べた。別のプロセスで2回実行し、配置の結果の SHA-256 を比べた。

## 結果

| 案 | 列の順の違反 | 枠の外にはみ出したメンバー | 同じプロセスの2回 | 別のプロセスの2回 |
| --- | --- | --- | --- | --- |
| A | なし | なし | 一致 | 一致 |
| B | なし | なし | 一致 | 一致 |

測った値の全体：[evidence/0006-elk-partition/result.md](evidence/0006-elk-partition/result.md)

## 観察

1. **パーティションで、入れ子のグループを含む列を、左から右の順に並べられた。** 列の左端の x 座標は、案 A で、ユーザー 12、CDN 242、VPC 477、IdP と決済代行 1236 だった。
2. **グループの中のノードにパーティションを付けても付けなくても、列の順とグループの枠の判定は同じだった。** 配置の結果そのもの（SHA-256）は、案 A と B で違った。
3. **ELK の配置の結果の JSON には、実行のたびに値が変わる `$H`（ELK の中のオブジェクトの番号）が含まれる。** `$H` を除くと、2回の実行の結果は一致した。エンジンは配置の結果の座標だけを使うので、`$H` は出力に入らない。

## 限界

- **題材は X08 の1つだけである。** 列の中のノードが多い図や、列をまたぐ線が多い図は試していない。
- **線の経路、ラベル、文法の規則の検査は、この検証では見ていない。** 列の順と、グループの枠だけを見た。
- **Linux でしか確かめていない。**
