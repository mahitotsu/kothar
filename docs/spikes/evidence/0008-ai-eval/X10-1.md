## 確かめてほしい割り当て

1. **戻り線を1本にまとめました。** 設計書の「ADR の評価の途中で判断の基準を変えたくなった → 要件」は、最初 `a_adr → s3` の戻り線にしましたが、規則6の違反になりました（線が a_impl より上を通る）。そこで `s5 → s3` の線とまとめ、ラベルを「どう変えても要件を満たせない／ADR の判断の基準を変えたい」にしました。
2. **文書体系への参照の出どころを ADR を書く作業にしました。** 最初は段階1から出しましたが、規則9の違反になりました（`s1→s2` の線と重なる）。照合の表では、S3 と S4 の規則を使うのは ADR を書き直すときと置き換えるときなので、出どころを `a_adr` にしました。
3. **承認の線は1つの責任者ノードに集めました。** 段階1・2・3・5・6から線を引き、段階5の線には「ADR ごと」とラベルを付けました。規則5（上段のノードは承認を求める段階の真上にある）の違反は出ませんでした。ただ、5つの段階の真上に同時に置くことはできないので、1つのノードにまとめるのでよいか見てください。
4. **ゲートから次のサイクルへ戻る線は描いていません。** 段階6から段階1へ戻る線は、`next` で描くと規則4に違反します。また、設計書の「上流に戻るとき」にも挙がっていません。
5. **「リスクを先に確かめる検証」と「AI エージェントの作業の決まり」の節はモデルに入れていません。** 段階の流れの外にある例外と作業の決まりなので、この語彙と文法では描く場所がないと判断しました。
