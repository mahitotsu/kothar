### 検査で直したところ
最初の lint では、線の重なり（規則9）が3件出ました。

- **承認の線の向きを逆にしました。** 最初は「責任者 → 段階」と書いていました。すると承認の線が段階の下の辺に入り、上流に戻る線や「段階の中で行う」線とぶつかりました。文法の「上の段は承認を求める段階の真上」と、承認の線は「上の辺から出て下の辺に入る」という決まりに合わせ、「段階 → 責任者」に直しました。
- **文書体系を参照する線の出どころを変えました。** 「1. 約束」から引くと「1. 約束 → 2. 体験」の線と重なりました。そこで、規則 S3、S4 を実際に使う作業である「ADR を書く」から引くようにしました。

### レビューで見てほしい判断
1. **上流に戻る線は2本だけにしました。** 「5. 収束 → 4. 仕様の仮説」と「5. 収束 → 3. 要件」です。設計書の表の4行目「要件を変えると約束が果たせなくなる → PR/FAQ」は、「次のゲートで見直す。それまでは約束を変えない」とあり、すぐに戻る線ではないので描いていません。3行目の「判断の基準を変えたい」は、戻る先が同じ要件なので、2行目と同じ線にまとめました。
2. **ゲートから計画への参照の線は、私の読み取りです。** 設計書に直接の参照は書かれていません。
3. **作業者のノードは置いていません。** 役割の表にはありますが、語彙に承認以外で役割とつなぐ線の種類がなく、置き場所がないためです。
4. **「リスクを先に確かめる検証」は描いていません。** 要件より前に行う例外の流れで、今の文法ではうまく表せないためです。
5. **「6. ゲート」から次のサイクルの「1. 約束」へ戻る線はありません。** 次の段階へ進む線は左から右へ描く決まり（規則4）があるので、引いていません。
