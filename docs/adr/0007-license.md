# ADR 0007: ライセンス

- 状態：承認
- 日付：2026-10-05

## 背景

リポジトリを公開し、npm の CLI と Claude Code のプラグインとして配布する前に、ライセンスを決める必要がある。依存する elkjs は EPL-2.0 で、npm の依存として利用者の環境に別に入る。同梱するフォントのライセンスとの整合も要る（ADR 0006）。

## 判断の基準

1. 利用者が業務の図で使うときに、制約が少ないこと
2. 依存と同梱物のライセンスと両立すること
3. 条文が短く、利用者がすぐ理解できること

## 検討した選択肢

### 1. MIT

- 長所：制約が最も少なく、npm の CLI で最も一般的である（基準1、基準3）。elkjs の EPL-2.0 とも、同梱を許すフォントのライセンスとも両立する（基準2）。
- 短所：特許の許諾を明記しない。

### 2. Apache-2.0

- 長所：MIT と同じく制約が少なく、特許の許諾と商標の扱いを明記する（基準1）。
- 短所：条文が長い（基準3）。

### 3. EPL-2.0

- 長所：ELK と同じライセンスで、ELK に手を入れて取り込む場合に扱いがそろう。
- 短所：改変したファイルの公開を求める弱いコピーレフトで、利用者の制約が増える（基準1）。

### 4. まだ公開しない

- 長所：あとからどのライセンスでも選べる。
- 短所：公開して使ってもらうことができない。

## 決定

選択肢1の MIT を採る。リポジトリのルートに `LICENSE` を置き、各パッケージとプラグインのメタデータにも `MIT` を書く。

## 帰結

- elkjs のソースを取り込んで改変する場合は、その部分に EPL-2.0 が残るので、別のディレクトリに分けて扱う。
- 同梱するフォントは、MIT の配布物に含められるライセンス（SIL Open Font License など）のものから選ぶ。
