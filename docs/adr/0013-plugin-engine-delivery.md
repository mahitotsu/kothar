# ADR 0013: プラグインにエンジンを届ける方式

- 状態：承認
- 日付：2026-10-09

## 背景

ADR 0012 で、プラグインの `bin/kothar` からエンジンの CLI を起動すると決めた。プラグインを入れた環境に、エンジンをどう届けるかを決める必要がある。

エンジンは、リポジトリの `packages/` に TypeScript のまま置いてあり、Node.js の型の除去で実行している（ADR 0005）。一方で、マーケットプレイスから入れたプラグインは、プラグインのディレクトリだけがキャッシュに写され、その外のファイルは写されない（[Plugin loading reference](https://code.claude.com/docs/en/plugins/loading.md)）。プラグインから `packages/` のエンジンは使えない。

## 判断の基準

優先順に並べる。

1. マーケットプレイスから入れたプラグインで、エンジンが動くこと（必須）。判定：プラグインを入れるだけで、ほかの手順なしに `bin/kothar` が動くか。出どころ：R-PLUGIN-1
2. Agent SDK でディレクトリから読み込んだプラグインで、エンジンが動くこと（必須）。判定：プラグインのディレクトリを読み込むだけで、ほかの手順なしに `bin/kothar` が動くか。出どころ：R-PLUGIN-2
3. プラグインのエンジンが、CLI と同じ図を描くこと（必須）。判定：同じモデルから、CLI と同じ SVG と JSON が出るか。出どころ：R-AI-5
4. 配布し、版をそろえる手間が少ないこと。判定：プラグインのほかに配布するものの数を比べる。出どころ：ADR 0004

## 検討した選択肢

### 1. TypeScript のまま npm に公開し、プラグインの依存にする

エンジンを TypeScript のまま npm に公開し、プラグインの `package.json` の依存にする。

- 長所：エンジンのソースをそのまま公開でき、ビルドの手順が要らない（基準4）。
- 短所：Node.js は `node_modules` の中の TypeScript のファイルを扱わないので、依存として入れたエンジンは動かない（基準1、基準2、基準3。[検証 0007](../spikes/0007-plugin-reach.md)、[Node.js の TypeScript](https://nodejs.org/api/typescript.html)）。npm とプラグインの2つを配布する（基準4）。

### 2. JavaScript にビルドして npm に公開し、プラグインの依存にする

エンジンを JavaScript にビルドして npm に公開し、プラグインの `package.json` とロックファイルで依存にする。

- 長所：マーケットプレイスから入れたプラグインには、Claude Code がロックファイルに従って依存を入れる（基準1。Plugin loading reference の Node.js package dependencies）。CLI と同じソースからビルドする（基準3）。
- 短所：依存を自動で入れるのは、プラグインをキャッシュに写すときだけで、その場で読み込むプラグインには入れない（基準2。Plugin loading reference）。Agent SDK は、プラグインのディレクトリをその場で読み込むので、利用者が依存を入れる手順が要る（基準2）。npm とプラグインの2つを配布し、版をそろえる（基準4）。

### 3. エンジンを1つのファイルにまとめ、プラグインの中に置く

エンジンと依存のパッケージを、esbuild で1つの JavaScript のファイルにまとめ、JSON Schema とフォントと一緒にプラグインの中に置く。`bin/kothar` はそのファイルを Node.js で起動する。

- 長所：プラグインのディレクトリの中だけで動き、`node_modules` も要らない（基準1、基準2。検証 0007）。マーケットプレイスから入れると、プラグインのディレクトリはキャッシュに写される（基準1。Plugin loading reference）。まとめたファイルは、元の CLI と同じ SVG と JSON を出した（基準3。検証 0007）。プラグインのほかに配布するものがない（基準4）。
- 短所：まとめたファイル（約 5.8MB）とフォント（4.6MB）を、プラグインの中にコミットする。エンジンを変えるたびに、まとめ直す必要がある（基準4）。マーケットプレイスから入れたプラグインで動くかは、試していない（基準1。検証 0007 の限界）。

### 対照表

| 選択肢 | 基準1 | 基準2 | 基準3 | 基準4 |
| --- | --- | --- | --- | --- |
| 1. TypeScript のまま npm に公開する | × | × | × | △ |
| 2. JavaScript にビルドして npm に公開する | ○ | × | ○ | △ |
| 3. 1つのファイルにまとめてプラグインに置く | ○ | ○ | ○ | △ |

## 決定

選択肢3の「エンジンを1つのファイルにまとめ、プラグインの中に置く」を採る。必須の基準1〜3をすべて満たすのは、選択肢3だけである。

## 帰結

- プラグインは、それだけで動く。npm への公開は、プラグインの前提にならない。CLI を npm で配る（PR/FAQ の `npx kothar`）ための公開は、別に扱う。
- まとめたファイルとフォントで、リポジトリが約 10MB 大きくなる。
- エンジンを変えたら、まとめ直してコミットする。まとめたファイルがソースから作ったものと一致するかを、CI で確かめる。
- マーケットプレイスから入れたプラグインで `bin/kothar` が動かなかったら、この決定を見直す。
