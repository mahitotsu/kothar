# ADR 0012: プラグインからエンジンを呼ぶ方式

- 状態：承認
- 日付：2026-10-09

## 背景

ADR 0004 で、エンジンを CLI として使えるようにし、プラグインはエンジンを呼ぶと決めた。呼ぶ方式（CLI を呼ぶか、MCP サーバーを置くか）は、別に決めるとした。フェーズ3では、プラグインのスキルが、AI にエンジンでモデルを検査させ、図を描かせる（S-PLUGIN-2、S-PLUGIN-3）。スキルの書き方が呼ぶ方式で変わるので、スキルを書く前に決める。

開発と保守は一人で行うので、呼ぶために自前で作り、保守するものが少ないことを基準にする。また、利用者が CLI を使うときと、AI がスキルの中でエンジンを使うときに同じコマンドを使えれば、使い方の説明とエラーの文を1つにできる。この2つは要件と約束からは直接導けないので、出どころを「この ADR」とする。

## 判断の基準

優先順に並べる。

1. Claude Code と Claude Agent SDK の両方で、AI がエンジンを呼べること（必須）。判定：両方で、プラグインを読み込んだ AI がエンジンを呼べたか。出どころ：R-PLUGIN-1、R-PLUGIN-2
2. AI が描いた図が、同じモデルから CLI で描いた図と同じであること（必須）。判定：AI が呼ぶものが、CLI と同じエンジンか。出どころ：R-AI-5
3. 呼ぶために自前で作り、保守するものが少ないこと。判定：CLI のほかに作るものを比べる。出どころ：この ADR
4. AI と利用者が、同じコマンドでエンジンを使えること。判定：スキルの中で AI が使うコマンドが、利用者が CLI で使うコマンドと同じか。出どころ：この ADR

## 検討した選択肢

### 1. プラグインの bin/ に kothar コマンドを置く

プラグインの `bin/` に、エンジンの CLI を起動する `kothar` コマンドを置く。スキルは、AI に Bash ツールで `kothar lint` などを実行させる。

- 長所：`bin/` のコマンドは、Claude Code でも Agent SDK でも、AI が呼べた（基準1。[検証 0007](../spikes/0007-plugin-reach.md)）。呼ぶのは CLI そのものである（基準2）。CLI のほかに作るのは、CLI を起動する小さなスクリプトだけである（基準3）。AI が使うコマンドは、利用者が使う `kothar` と同じである（基準4）。
- 短所：`bin/` を持つプラグインは、claude.ai と Cowork では入れられない（[Plugin manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference.md) の Standard layout）。Kothar が約束するのは Claude Code と Agent SDK だけ（P8）なので、基準1には当たらないが、使える場所が限られる（基準1）。

### 2. スキルの本文に、エンジンのパスを書く

スキルの本文に、`${CLAUDE_PLUGIN_ROOT}` で始まるエンジンのパスを書き、AI にそのパスのコマンドを実行させる。

- 長所：スキルの本文の `${CLAUDE_PLUGIN_ROOT}` は、Claude Code でも Agent SDK でも、プラグインの絶対パスに置き換わり、AI が呼べた（基準1。検証 0007）。呼ぶのは CLI そのものである（基準2）。CLI のほかに作るものはない（基準3）。
- 短所：AI が使うコマンドは、プラグインの絶対パスで始まる長いコマンドになり、利用者が使う `kothar` と違う（基準4）。

### 3. MCP サーバーを置く

プラグインに MCP サーバーを置き、render、lint、check を MCP の道具として出す。

- 長所：Agent SDK でもプラグインの MCP サーバーを使える（基準1。[Plugins in the SDK](https://code.claude.com/docs/en/agent-sdk/plugins.md)）。MCP サーバーの中から同じエンジンを呼べば、同じ図になる（基準2）。
- 短所：MCP サーバーを自前で作り、MCP の SDK に依存する（基準3）。AI が使うのは MCP の道具で、利用者が使う CLI のコマンドと違う（基準4）。プラグインの MCP サーバーから呼べるかは、確かめていない（基準1）。

## 決定

選択肢1の「プラグインの bin/ に kothar コマンドを置く」を採る。必須の基準1と2を満たすのは選択肢1と2で、そのうち基準4で優れるのは選択肢1である。

## 帰結

- スキルは、AI に `kothar render`、`kothar lint`、`kothar check` を実行させる。利用者向けの CLI の説明と、エラーの文を、そのまま AI も使う。
- `bin/kothar` が起動するエンジンを、プラグインを入れた環境でどう手に入れるかは、ADR 0013 で決める。
- Kothar のプラグインは、claude.ai と Cowork では入れられない。
- Claude Code か Agent SDK のどちらかで、プラグインの `bin/` のコマンドを AI が呼べなくなったら、この決定を見直す。
