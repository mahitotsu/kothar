# ADR 0006: 文字幅の測り方

- 状態：承認
- 日付：2026-10-05

## 背景

ノードの大きさとラベルの位置は、文字幅で決まる。文字幅がずれると、ラベルの重なりの判定と配置の結果が変わる。Kothar は、同じ入力から Linux でも macOS でもバイト単位で同じ配置の結果を出すと約束している（ADR 0002）。

## 判断の基準

1. 実行環境によらず、同じ文字幅が得られること
2. 実際に描いたときの文字幅と合っていること

## 検討した選択肢

### 1. システムのフォントで測る

- 長所：表示する環境のフォントで測るので、その環境では見た目の幅と一致しやすい（基準2）。配布物にフォントを含めずに済む。
- 短所：実行環境ごとに入っているフォントが違い、決定性が崩れる（基準1）。

### 2. 文字の種類ごとの係数で見積もる

全角を 1em、半角を 0.6em とする、など。検証 0001 ではこの方法で代用した。

- 長所：実装が最も簡単で、決定性も保てる（基準1）。配布物にフォントを含めずに済む。
- 短所：実際の幅とずれ、ラベルの重なりの判定が不正確になる（基準2）。

### 3. フォントファイルを同梱し、そのメトリクスを読んで測る

- 長所：決定性を保ちつつ、描画に使うフォントと幅が一致する（基準1、基準2）。
- 短所：配布物が大きくなる。同梱を許すライセンスのフォントに限られる。表示する環境に同じフォントがなければ、見た目の幅はずれる。

## 決定

選択肢3を採る。

## 帰結

- フォントファイルを配布物に含めるので、ライセンスが同梱を許すフォントを選ぶ必要がある。
- SVG を表示する環境に同じフォントがないと、見た目の幅は測った幅とずれる。SVG にフォントを埋め込むかは、別に決める。
