# ADR 0006: 文字幅の測り方

- 状態：承認
- 日付：2026-10-06

## 背景

ノードの大きさとラベルの位置は、文字幅で決まる。文字幅がずれると、配置の結果と、ラベルの重なりの検査の結果が変わる。配置の結果を JSON で出すエンジンを作る前に、文字幅の測り方を決める必要がある。

## 判断の基準

優先順に並べる。

1. 実行環境によらず、同じ文字幅が得られること（必須）。判定：同じ文字列について、Linux と macOS で同じ幅が得られるか。出どころ：P6
2. 測った幅が、描いたときの幅と合っていること。判定：Kothar が SVG に指定するフォントで描いたときの幅と、測った幅が一致するか。出どころ：P5

## 検討した選択肢

### 1. システムのフォントで測る

実行する環境に入っているフォントで、文字幅を測る。

- 長所：その環境で描けば、測った幅と描いた幅が一致する（基準2）。
- 短所：実行環境ごとに入っているフォントが違うので、環境によって幅が変わる（基準1）。

### 2. 文字の種類ごとの係数で見積もる

全角を 1em、半角を 0.6em のように、文字の種類ごとの係数で幅を見積もる。

- 長所：計算だけで決まるので、環境によらず同じ幅になる（基準1）。
- 短所：見積もりなので、実際のフォントで描いた幅とずれ、ラベルの重なりの判定が変わりうる（基準2。[検証 0001](../spikes/0001-elk-layout.md) の限界）。

### 3. フォントファイルを同梱し、そのメトリクスを読んで測る

配布物にフォントファイルを含め、そのメトリクスから幅を測る。SVG には同じフォントを指定する。

- 長所：同梱したファイルから測るので、環境によらず同じ幅になる（基準1）。SVG に指定するフォントと同じフォントで測るので、描いた幅と一致する（基準2）。
- 短所：SVG を表示する環境にそのフォントがなければ、表示される幅は測った幅とずれる（基準2）。

### 対照表

| 選択肢 | 基準1 | 基準2 |
| --- | --- | --- |
| 1. システムのフォントで測る | × | ○ |
| 2. 文字の種類ごとの係数で見積もる | ○ | × |
| 3. フォントファイルを同梱する | ○ | △ |

## 決定

選択肢3の「フォントファイルを同梱し、そのメトリクスを読んで測る」を採る。必須の基準1を満たす選択肢のうち、基準2で選択肢2より優れるためである。

## 帰結

- フォントファイルを配布物に含めるので、配布物が大きくなる。ライセンスが同梱を許すフォントを選ぶ必要がある（ADR 0007）。
- SVG を表示する環境に同じフォントがないと、表示される幅は測った幅とずれる。
- 同梱を許すライセンスで、図に使う文字（日本語を含む）をすべて持つフォントが見つからなければ、この決定を見直す。
