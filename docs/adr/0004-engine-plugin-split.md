# ADR 0004: エンジンとプラグインの役割分担

- 状態：提案
- 日付：2026-10-06

## 背景

Kothar は、Claude Code のプラグインを利用者の入口とし、Claude Agent SDK からも使えるようにする。一方で、CI では AI を使わずに図を描き、検査できるようにする。配置と検査を行うエンジンと、AI の機能を持つプラグインに、それぞれ何を持たせるかを決める必要がある。AI に任せる範囲は ADR 0003 で決めた。

開発と保守は一人で行うので、配布物を増やすほど、版をそろえる手間が負担になる。そのため、配布の手間を基準の1つにする。これは PR/FAQ の約束からは直接導けないので、出どころを「この ADR」とする。

## 判断の基準

優先順に並べる。

1. 配置と検査を、AI を使わずにコマンドから実行できること（必須）。判定：Claude Code も Claude Agent SDK もない環境で、npm のコマンドとして図を描き、検査できるか。出どころ：ADR 0003、P8、P12
2. Claude Code と Claude Agent SDK から、同じ機能を使えること（必須）。判定：同じ配布物を、両方から読み込めるか。出どころ：P8
3. 配布し、版をそろえる手間が少ないこと。判定：配布物の数と、版をそろえる必要がある組の数を比べる。出どころ：この ADR

## 検討した選択肢

### 1. プラグインにエンジンを含める

エンジンをプラグインの中のスクリプトとして持ち、npm には配布しない。

- 長所：Claude Agent SDK はプラグインを読み込めるので、Claude Code と同じ配布物を使える（基準2。[Agent SDK のプラグイン](https://code.claude.com/docs/en/agent-sdk/plugins.md)）。配布物が1つで済む（基準3）。
- 短所：プラグインの中のスクリプトを直接実行すれば CI でも動くが、npm のコマンドとしては使えず、ほかのツールから呼びにくい（基準1）。

### 2. エンジンを npm のパッケージにし、プラグインはそれを呼ぶ

エンジン（文法のコンパイラ、レイアウト、レンダラー、リンター）と CLI を npm のパッケージとして配布する。プラグインは、AI の機能（スキル）と、編集のたびに検査を走らせる仕組み（フック）を持ち、エンジンを呼ぶ。

- 長所：エンジンは npm のコマンドとして、AI なしで実行できる（基準1）。プラグインは Claude Code と Claude Agent SDK の両方から読み込め、プラグインのフックと MCP サーバーはコマンドを実行でき、依存のパッケージ（`node_modules` など）を置く場所として `${CLAUDE_PLUGIN_DATA}` が用意されているので、npm のパッケージをプラグインから呼べる（基準2。[Agent SDK のプラグイン](https://code.claude.com/docs/en/agent-sdk/plugins.md)、[プラグインの定義](https://code.claude.com/docs/en/plugins/manifest-reference.md)）。
- 短所：npm のパッケージとプラグインの2つを配布し、版をそろえる必要がある（基準3）。

### 対照表

| 選択肢 | 基準1 | 基準2 | 基準3 |
| --- | --- | --- | --- |
| 1. プラグインにエンジンを含める | △ | ○ | ○ |
| 2. エンジンを npm のパッケージにする | ○ | ○ | △ |

## 決定

選択肢2の「エンジンを npm のパッケージにし、プラグインはそれを呼ぶ」を採る。必須の基準1を満たすのは、選択肢2だけである。

- `packages/core` に文法のコンパイラ、レイアウト、レンダラー、リンターを置き、`packages/cli` から `render`、`lint`、`check` として使う。
- `plugins/kothar` には、文法とモデルの書き方を教えるスキル、設計書からモデルを下書きして検査を通るまで直すスキル、モデルや文法を編集したら検査と描画を走らせるフックを置く。
- リポジトリ自体を Claude Code のマーケットプレイスにし、ルートの `.claude-plugin/marketplace.json` で配布する。
- 開発中のスキルは `.claude/skills/` に置いて使いながら育て、AI の機能を扱うフェーズでプラグインに移す。

プラグインからエンジンをどう呼ぶか（CLI を呼ぶか、MCP サーバーを置くか）は、この ADR では決めない。

## 帰結

- CI では、npm のコマンドだけで図を検査できる。
- プラグインは npm のパッケージに依存するので、両者の版をそろえて配布する必要がある。
- Claude Agent SDK からプラグインを読み込めない、またはプラグインから npm のパッケージを呼べないと分かったら、この決定を見直す。
