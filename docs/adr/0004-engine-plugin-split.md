# ADR 0004: エンジンとプラグインの役割分担

- 状態：承認
- 日付：2026-10-05

## 背景

Kothar は、npm の CLI と Claude Code のプラグインの両方で使えるようにする。どちらに何を持たせるかを決める必要がある。

## 判断の基準

1. 決定論的な処理が、AI の外で再現できること（ADR 0003）
2. CI やほかのツールから使えること
3. 配布の手間が少ないこと

## 検討した選択肢

### 1. プラグインにエンジンを持たせる

- 長所：配布物が1つで済む（基準3）。Claude Code の利用者は、プラグインを入れるだけで使える。
- 短所：Claude Code なしでは使えず、CI で図を検査できない（基準2）。決定論的な処理と AI の処理の境界があいまいになる（基準1）。

### 2. エンジンを CLI として完結させ、プラグインはそれを呼ぶ

- 長所：描画と検査が CLI だけで再現でき、CI やほかのツールから使える（基準1、基準2）。
- 短所：CLI とプラグインの2つを配布し、版を合わせる必要がある（基準3）。

## 決定

選択肢2を採る。

- `packages/core` に文法のコンパイラ、レイアウト、レンダラー、リンターを置き、`packages/cli` から `render`、`lint`、`check` として使う。
- `plugins/kothar` には、文法とモデルの書き方を教えるスキルと、モデルや文法を編集したら lint と描画を走らせるフックを置く。
- リポジトリ自体を Claude Code のマーケットプレイスにし、ルートの `.claude-plugin/marketplace.json` で配布する。
- 開発中のスキルは `.claude/skills/` に置いて使いながら育て、設計書からモデルを作るフェーズでプラグインに移す。

## 帰結

- CI では CLI だけで図を検査できる。
- プラグインは CLI に依存するので、CLI とプラグインの版を合わせて配布する必要がある。
