# ADR 0003: LLM に任せる範囲

- 状態：承認
- 日付：2026-10-05

## 背景

設計書から図を作る作業には、LLM が役に立つ。一方で、LLM の生成は決定論的でないので、図のコードや座標を LLM に書かせると、設計書を直して生成し直すたびに配置が変わる。LLM をどこまで使うかを決める必要がある。

## 判断の基準

1. 同じ入力から同じ図が出ること
2. 人がレビューできる単位で LLM の出力を受け取れること
3. 設計書から図を作る手間が減ること

## 検討した選択肢

### 1. LLM に図のコードを書かせる

AWS の diagram スキルなどの方法。

- 長所：設計書から図までを一度に作れ、手間が最も減る（基準3）。既にツールがある。
- 短所：生成のたびに配置が変わり、図の差分をレビューできない（基準1）。出力が図のコードなので、意味の割り当てが正しいかをレビューしにくい（基準2）。

### 2. LLM を使わない

- 長所：決定性が自明に保たれる（基準1）。仕組みが単純である。
- 短所：設計書からモデルを書き起こす手間が残る（基準3）。

### 3. LLM にはモデル（要素、線、属性）の下書きだけを作らせ、座標は CLI が決める

- 長所：モデルが同じなら図も同じになる（基準1）。人はモデルという小さな単位でレビューできる（基準2）。
- 短所：モデルのレビューは人に残るので、選択肢1ほど手間は減らない。LLM にモデルの書き方を教えるスキルを用意する必要がある。

## 決定

選択肢3を採る。LLM が触るのは、設計書からモデルへの変換だけとする。モデルから図までは、すべて CLI で再現できるようにする。

## 帰結

- LLM を使っても、図の配置は揺れない。モデルが同じなら図も同じである。
- LLM の出力の品質は、手で作ったモデルとの比較（ノード、線、線の種類、領域の割り当てごとの適合率と再現率）で測れる。
- LLM の機能は、モデルの形が固まるまで入れない。
