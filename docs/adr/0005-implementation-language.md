# ADR 0005: 実装言語

- 状態：承認
- 日付：2026-10-06

## 背景

エンジンと CLI の実装言語を決める必要がある。エンジンは npm のパッケージとして配布し、プラグインから呼ぶ（ADR 0004）。配置には ELK を使う見込みである（ADR 0001、提案）。実装を始める前に決める必要がある。

## 判断の基準

優先順に並べる。

1. npm で配布でき、npx で実行できること（必須）。判定：npm のパッケージとして公開し、利用者が別の実行環境を入れずに npx で実行できるか。出どころ：ADR 0004、P8
2. 出力の SVG と JSON を、バイト単位で制御できること（必須）。判定：描画のライブラリを使わずに、出力を文字列として組み立てられるか。出どころ：P6、P10
3. ELK をそのまま使えること。判定：ELK を、別の実行環境を用意せずに呼べるか。出どころ：ADR 0001

## 検討した選択肢

### 1. Python

既存の diagrams と同じ言語で実装する。

- 長所：出力を文字列として組み立てられる（基準2）。
- 短所：npm で配布できない（基準1）。ELK を使うには、Java か JavaScript の実行環境を別に用意する必要がある（基準3）。

### 2. Java

ELK の本体と同じ言語で実装する。

- 長所：出力を文字列として組み立てられる（基準2）。ELK のすべての機能を変換なしで使える（基準3）。
- 短所：npm での配布に向かず、利用者に JVM を求める（基準1）。

### 3. TypeScript

Node.js で動く TypeScript で実装し、ELK は JavaScript に変換した elkjs を使う。

- 長所：npm でそのまま配布でき、npx で実行できる（基準1）。出力を文字列として組み立てられる（基準2）。elkjs で ELK を呼べることは、検証 0001 で確かめた（基準3。[検証 0001](../spikes/0001-elk-layout.md)）。
- 短所：elkjs は Java からの機械的な変換なので、Java 版より遅く、内部の不具合を追いにくいおそれがあるが、どちらも確かめていない（基準3）。

### 対照表

| 選択肢 | 基準1 | 基準2 | 基準3 |
| --- | --- | --- | --- |
| 1. Python | × | ○ | × |
| 2. Java | × | ○ | ○ |
| 3. TypeScript | ○ | ○ | △ |

## 決定

選択肢3の「TypeScript」を採る。必須の基準1を満たすのは、選択肢3だけである。

- 配置には elkjs を使い、SVG は描画のライブラリを使わずに直接出力する。
- 開発中は、Node.js（24 以上）の型の除去で `.ts` をそのまま実行し、型の検査だけを `tsc --noEmit` で行う。

## 帰結

- 利用者の環境に Node.js が要る。
- ADR 0001 で ELK を使わない方式を採ったら、基準3を除いて比べ直す。必須の基準だけでも選択肢3が残るので、決定は変わらない見込みである。
