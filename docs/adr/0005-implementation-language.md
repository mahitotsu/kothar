# ADR 0005: 実装言語

- 状態：承認
- 日付：2026-10-05

## 背景

エンジンと CLI の実装言語を決める必要がある。配置には ELK を使う見込みで（ADR 0001）、配布は npm の CLI とする（ADR 0004）。

## 判断の基準

1. ELK をそのまま使えること
2. npm で配布でき、`npx` で実行できること
3. 出力の SVG を細かく制御できること

## 検討した選択肢

### 1. Python

- 長所：既存の diagrams と同じ言語で、そのアイコンなどの資産を使いやすい。
- 短所：ELK を使うには Java か JavaScript の実行環境を別に用意する必要がある（基準1）。npm で配布できない（基準2）。

### 2. Java

- 長所：ELK の本体と同じ言語で、ELK のすべての機能を変換なしで使える（基準1）。
- 短所：npm での配布に向かず、利用者に JVM を求める（基準2）。

### 3. TypeScript

- 長所：ELK を JavaScript に変換した elkjs が使え、npm でそのまま配布できる（基準1、基準2）。SVG は文字列として直接組み立てられる（基準3）。
- 短所：elkjs は Java からの機械的な変換なので、Java 版より遅く、内部の不具合を追いにくい。型定義が実体と合わない箇所がある。

## 決定

選択肢3を採る。配置には elkjs を使い、SVG は描画ライブラリを使わずに直接出力する。

開発中は、Node.js（24 以上）の型の除去で `.ts` をそのまま実行し、型の検査だけを `tsc --noEmit` で行う。

## 帰結

- elkjs の型定義は CommonJS の実体と合わない箇所があり、読み込みに型の変換が要る。
- 配布するときにビルドの手順が要るかは、npm への公開の前に決める。
