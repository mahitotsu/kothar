# ADR 0001: レイアウトの方式

- 状態：提案
- 日付：2026-10-05

## 背景

Kothar は、文法から作った制約に従って図を配置する。配置のエンジンを何で作るかは、このプロジェクトで最もリスクの大きい技術判断であり、文法の語彙やモデルの形より先に決める必要がある。

文法が配置に求めることは、流れの向き、線の出入りの辺、グループ、領域（上段、本流、下段、端の列）の4つである。前の3つは自動レイアウトのエンジンがもともと扱う。領域は、汎用のエンジンには対応する概念がない。

## 判断の基準

優先順に並べる。

1. 文法の不変条件を、ピン留めなしで満たせること
2. 同じ入力から、同じ出力がバイト単位で出ること
3. グループを、メンバーだけを囲む枠として保てること
4. 作るものと保守するものが少ないこと
5. 線の交差や折れ曲がりが少ないなど、見た目が整っていること

## 検討した選択肢

根拠は [検証 0001](../spikes/0001-elk-layout.md) による。

### 1. ELK だけで配置する

文法を、流れの向き、ポートの辺、入れ子のノードに変換して ELK に渡す。

- 長所：流れの向き、線の出入りの辺、グループは守られた（基準1の一部、基準3）。決定性も保たれた（基準2）。自前で持つ処理は、文法を ELK の入力に変換する部分だけで済む（基準4）。
- 短所：領域を表す手段がない。上段のノードは呼び出す側の真上に来ず、端の列も全体の右に来なかった（基準1）。

### 2. ELK に層の制約を足す

選択肢1に加えて、文法から計算した層と層内の順序を ELK の制約として渡す。文法から粗い座標を作り、ELK の対話モードに渡す方法も含む。

- 長所：配置がすべて ELK の中で完結し、自前の配置の処理を持たずに済む（基準4）。
- 短所：入れ子のグラフでは制約が一部しか効かず、違反は選択肢1から減らなかった。平らなグラフにすると層の指定は効くが、上段を呼び出す側と同じ層に置くことは ELK が満たさず、グループも壊れた（基準1、基準3）。対話モードに渡す方法は、違反が最も多かった。

### 3. 本体を ELK で配置し、周辺の領域を文法から置く（二段構成）

本流、下段、グループからなる本体だけを選択肢1と同じく ELK で配置し、上段と端の列は文法の規則（呼び出す側の真上、全体の右）に従って本体の外に置く。

- 長所：検証の題材では、7つの不変条件をすべて満たした（基準1）。決定性とグループは選択肢1と同じく保たれる（基準2、基準3）。
- 短所：周辺の領域の配置と、そこへの線の経路を自前で持つ（基準4）。ELK の交差の最小化は周辺の領域に及ばないので、本体と周辺の間で交差や重なりが起きうる（基準5）。本体の中の帯の順序（下段が本流より下）は、題材では満たされたが、制約として強制できていない（基準1）。

### 4. 制約ソルバーで配置する

文法を線形の制約に変換し、kiwi.js などで解く。

- 長所：領域や帯の順序を含めて、文法をそのまま制約として表せる見込みがある（基準1）。
- 短所：線の経路づけ、交差の最小化、グループの枠の計算を自前で作ることになる（基準4、基準5）。検証していないので、見込みの裏づけがない。

## 決定

選択肢3の二段構成を採る。

文法のコンパイラが、モデルを本体と周辺の領域に分け、逆向きの線を反転し、線の出入りの辺をポートに変換する。本体を elkjs の layered で配置し、周辺の領域を文法の規則に従って本体の外に置く。

## 帰結

- 流れの向き、線の出入りの辺、グループ、線の経路といった重い処理は ELK に任せられる。自前で持つのは、周辺の領域の配置と、そこへの線だけで済む。
- 逆向きの線を反転して渡すことが、文法のコンパイラの責務になる。反転しないと、ELK が閉路を壊すときに本流の線を反転することがある。
- 周辺の領域の配置は ELK の最適化の外にあるので、本体と周辺の間で交差や重なりが起きうる。これはリンターで検出する。
- 本体の中の帯の順序（下段が本流より下にあること）は、ELK の制約では強制できていない。検証の題材で満たされたのは配置の結果である。ベンチマークの図でこれが破れ、ELK の範囲で直せない場合は、この決定を見直し、選択肢4を検証する。
- 根拠は図1枚の検証である。2種類目の図を扱うフェーズで、この決定が保てるかを確かめる。
