# 設計書から Kothar のモデルを下書きする

Kothar は、配置の約束事（文法）とモデルから図を描く。あなたが書くのはモデルだけである。座標や配置は書かない。配置は Kothar のエンジンが決める。

## 1. 読む

次のものを読む。どれがどこにあるかが依頼から分からなければ、描く人に確かめる。

- 設計書
- 語彙のファイル（`vocabulary.yaml` など）：使える属性のキーと値、線の種類。コメントに意味が書いてある
- 文法のファイル（`grammar.yaml` など）と、その説明（同じディレクトリの `.md`）：属性と線の種類が、図のどこにどう描かれるか

## 2. モデルを書く

設計書の要素とつながりを、語彙の言葉に当てはめて、モデルの YAML を書く。置き場所の指定がなければ、文法と同じディレクトリの `model.yaml` に書く。そのファイルがすでにあるときは、上書きせずに描く人に確かめる。

```yaml
vocabulary: vocabulary.yaml   # モデルのファイルからの相対パス
grammar: grammar.yaml

nodes:
  - { id: s1, label: 1. 約束, attrs: { element: stage } }
groups:
  - { id: cycle, label: サイクル, members: [s1] }
edges:
  - { from: s1, to: s2, kind: next, label: 任意のラベル }
```

守ること：

- 属性（`attrs`）のキーと値、線の種類（`kind`）は、語彙にあるものだけを使う。
- `id` は英字で始め、英数字、`_`、`-` だけを使う。
- `label` は、設計書での呼び名をそのまま使う。
- 座標とピン留め（`pin`）は書かない。
- 設計書に書かれていない要素やつながりを足さない。

## 3. 検査して直す

Bash ツールで次を実行する。`kothar` はこのプラグインのコマンドである。

```
kothar lint <モデルのファイル>
```

- 「入力に誤りがあります」と出たら、示された場所を直す。語彙にない属性は、示された候補から選ぶ。
- 違反が出たら、モデルの属性やつながりの割り当てを見直す。ピン留めでごまかさない。
- 「違反は0件です。」になるまで繰り返す。

## 4. 図を描く

```
kothar render <モデルのファイル> --out <モデルと同じディレクトリの、モデルと同じ名前の .svg>
```

## 5. 報告する

最後に、次を示す。

- 書いたモデルのファイルと、描いた図のファイルのパス
- ノードごとに、割り当てた属性と、設計書のどこ（節の名前か、文の一部）から読み取ったかの表

| ノード | 割り当てた属性 | 設計書の根拠 |
| --- | --- | --- |
| 1. 約束（s1） | `element: stage` | 「サイクル」の節の表の「1. 約束」 |

描く人は、この表とモデルを見て、意味の割り当てが正しいかをレビューする。
